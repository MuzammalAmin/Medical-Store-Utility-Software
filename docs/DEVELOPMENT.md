# Ayyaz Pharmacy Manager: developer guide

How to build, test and change the app. For how to _use_ it, see the [user guide](../README.md); the full specification is in [PRD.md](../PRD.md).

**Status:** Phase 1 (MVP) is complete: items with price & GST, CSV/Excel import, inventory by batch (FEFO, expiry), POS with 80mm receipts, held bills, voids, returns and basic reports. Phase 2 (purchases, suppliers, expenses, cash close) is next.

## Requirements

- Windows 10/11
- Node.js 24 LTS or newer
- No C++ build tools needed: the encrypted SQLite driver ships ready-made Windows binaries

## Getting started

```bash
npm install
npm run dev          # start the app with hot reload
```

On first start the app asks for the shop details and an owner account, then shows the **recovery key**.
For development, you can keep test data out of your real AppData folder:

```bash
AYYAZ_USER_DATA=./.dev-data npm run dev    # Git Bash
```

## Scripts

| Command                                                 | What it does                                                           |
| ------------------------------------------------------- | ---------------------------------------------------------------------- |
| `npm run dev`                                           | Run the app in development mode                                        |
| `npm run build`                                         | Type-check and build into `out/`                                       |
| `npm run dist`                                          | Build the Windows installer into `dist/`                               |
| `npm test`                                              | Unit and integration tests (Vitest)                                    |
| `npm run test:e2e`                                      | Build, then drive the real app with Playwright                         |
| `npm run lint` / `npm run typecheck` / `npm run format` | Code quality checks                                                    |
| `npm run db:generate`                                   | Create a new SQL migration after changing `electron/main/db/schema.ts` |
| `npm run icon`                                          | Redraw the app icon (`build/icon.png`)                                 |
| `npm run sample:data`                                   | Regenerate the dummy spreadsheets in `samples/`                        |

## Project layout

```
electron/
  main/          main process: start-up, window, security, IPC, database, services
  preload/       the only bridge to the UI (one allowlisted `invoke` function)
src/             React UI: app shell, features/, components/ui (design system)
shared/          code used by both sides
  domain/        pure business rules: money, GST, units, permissions (fully unit-tested)
  ipc/           the typed IPC contract (Zod schemas) shared by UI and main process
db/migrations/   SQL migrations (generated by drizzle-kit, plus hand-written triggers)
samples/         dummy import spreadsheets for testing
tests/e2e/       Playwright tests that run the built app
```

## How it fits together

- **UI → main process:** the UI calls `ipc('channel', input)` from `src/lib/ipc.ts`. For every call, the main process
  checks that the request came from the app's own page, checks the user's role, validates the input with the shared
  Zod contract, and filters the output through the contract too. Business rules live in `electron/main/services` and
  `shared/domain`, never in the UI.
- **Adding a feature:** add the channel to `shared/ipc/channels.ts` and `shared/ipc/contract.ts` (the compiler then
  requires a handler), write the service, register it in `electron/main/ipc/handlers.ts`, and build the screen under
  `src/features/`.

## Security summary (PRD §6.2)

- The database and every backup are encrypted (SQLCipher format, AES-256). The key is protected by Windows DPAPI, and
  the printable recovery key is the only other way to open the data.
- Electron is locked down: sandboxed renderer, context isolation, strict CSP, a custom `app://` protocol, no
  navigation or new windows, no device permissions, and production fuses (no `RUN_AS_NODE`, ASAR integrity checks).
- PINs are hashed with scrypt, accounts lock after 5 wrong PINs, the screen locks when idle, and sensitive actions
  ask for the PIN again.
- The audit log and stock movements are append-only, enforced by database triggers.

## Development notes

- **Running from VS Code's extension host:** some tools inherit `ELECTRON_RUN_AS_NODE=1`, which starts Electron as
  plain Node (`does not provide an export named 'BrowserWindow'`). Unset it before launching. The e2e helper already
  does this.
- **Install scripts:** npm 11 asks before running package install scripts. The SQLite driver's `node-gyp` script is
  intentionally _not_ approved, because the bundled prebuilt binary is used instead.
- **Known audit warnings:** `npm audit` reports moderate issues in build tools only (drizzle-kit's dev server and
  electron-builder dependencies). None of them ship inside the app.
